Focus protocol · focus_lane (open semantics)

In code this appears as focus_lane / focus_lane_active. We do not fix a single public meaning — it is a bounded-context switch your deployment can interpret.

⚪ Protocol open

focus_lane_active: false — multi-channel awareness, discussion mode, cautious defaults. Guild and research threads typically run here. Shadow often fires on planner_themes_N.

🔴 Protocol closed

focus_lane_active: true — focused lane: ingress queued, single-thread depth, stronger boundary. What “closed” protects or enables is left to your policy layer (trust, vulnerability, dyad work, etc.).

Why keep the name? Audit history + regime tags already use regime_focus_lane; renaming code is a migration, not a doc edit.
